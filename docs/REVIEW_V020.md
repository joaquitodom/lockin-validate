# Independent adversarial review of lockin-validate 0.2.0

Reviewer: an independent reviewer role (Claude Opus 5.5), not the author of the package. Date: 2026-10-28. Scope: the nine
0.2.0 checks, the 0.2.0 alert-noise reduction, the conclusion rule (no PASS without verification, CONFIRMED_ERROR only
with unambiguous evidence, documented thresholds) and a sample of the BYMA calendar. Nothing under `src/`, `cases/` or
the existing docs was modified.

## 1. Method

- 28 own cases in `cases_review_v020/`, generated by `cases_review_v020/_generator/make_review_cases.py`. The script is
  seeded, deterministic (regenerating gives byte-identical files: one sha256 over all files was
  `ae99ae28...` on both runs) and **does not import lockin_validate**.
- Expected outcomes were written by the generator from the planted problem and **committed before the tool was run**
  (commit `56c12c5`, "Pre-register independent review cases..."). No expected.json was edited after the run.
- Kinds: 13 subtle planted problems or verification gaps (`planted_subtle`, `planted_gap`), 12 clean packages
  designed to tempt a false positive (`clean_tempting`), 2 end-to-end packages with several problems, 1 LockIn-like
  holdout. Each expected.json has `kind`, `target_checks` and, where the expectation is a reviewer judgement, a
  `reviewer_note`.

Command and summary output:

```
$ uv run lockin-validate cases --dir cases_review_v020 --json <scratch>/review.json
...
18 of 28 cases with all expected outcomes
Unexpected NEEDS_REVIEW (case x check): 15; false positives: 4
```

Per-finding detail was read with the Python API (`audit(folder)`), which is what the CLI runs.

The six misses share one pattern: **the check returns PASS on a package it could not, or did not, verify**. Most of

where the check looks.

## 3. Findings ranked by severity

### HIGH

**H1. coverage_drift returns PASS when the inputs disappear entirely (V02).** Periods are built only from the rows
that exist (`d.groupby("_period")` in `_coverage_table`). A quarter with no fundamentals rows at all is not a
period with 0% coverage: it is not a period. The universe is active through 2024, `rules.yaml` declares the period
2016-2024 and signals are scored every month to 2024-12, yet:

```
coverage_drift  PASS  No coverage drift against the strategy's own history
     4 input fields measured; lowest coverage 97%. Scope: members the universe source can see.
```

This is the LockIn failure in its purest form: the test years have no inputs. The check that was built for that
lesson misses it whenever the vendor stops delivering instead of thinning out. Fix: derive the expected periods from
the union of the universe membership span, `rules.period`, the signals' decision dates and the trades, and count each
expected period with no rows as 0% coverage.

**H2. dividend_corporate_actions returns PASS with "0 dividend events checked" (V14).** Without
`unadjusted_prices.csv` only the frozen-after-event test runs. The check still says "Adjusted series consistent with
the declared events" for a series labelled `adjusted=true` that is in fact as-traded (every 3% dividend shows as a
3% drop on its ex-date):

```
dividend_corporate_actions  PASS  Adjusted series consistent with the declared events
     0 declared events applied with the expected step, no unexplained ratio break and no price frozen after an event
     (0 dividend events checked). Ex-day application not verifiable without unadjusted_prices.csv.
```

docs/CONVENTIONS.md section 5 rules this out. A body sentence admitting non-verification does not make the title
true. Fix: with no as-traded series and dividends declared, return NOT_EXECUTABLE (or NEEDS_REVIEW) for application.
Optionally, test the "adjusted" series itself: an ex-date return close to -D / C(t-1) on most ex-dates means the
dividend was not applied.

**H3. input_sufficiency raises CONFIRMED_ERROR on a case mismatch between rules.yaml and the CSV header (V06).** The
loader lowercases every header (`inputs.py`, `str(c).strip().lower()`), but `required_inputs` is not lowercased. An
owner who writes `ROE` in both places gets:

```
input_sufficiency  CONFIRMED_ERROR  Names scored with fewer than 75% of the declared inputs in 42 periods
     840 of 840 scored names ... had fewer than 3 of the 4 required inputs ... Inputs delivered in no table:
     ROE, Debt_To_Equity, Gross_Margin, FCF_Yield.
```

There are two defects. (a) The names should be matched case-insensitively, as headers are. (b) More generally, when
a required input is "delivered in no table", the evidence is that the *package* lacks a column. It is not evidence
that the *model* scored without it. That is ambiguous (the owner may simply not have exported it) and should be
NEEDS_REVIEW, never CONFIRMED_ERROR. `run` exits 1 on this case.

**H4. protocol_integrity raises CONFIRMED_ERROR on a single look with an unrecognised purpose (V10).** Any purpose
outside the five-word vocabulary becomes `other`, and `other` is in `CONTAMINATING`. One run labelled `holdout` (a
common synonym of test) gives:

```
protocol_integrity  CONFIRMED_ERROR  Reserved window(s) test used more than once (1 runs)
```

The title is false: the window was used once. Unknown purpose is a vocabulary problem and should be NEEDS_REVIEW
("purpose not recognised: holdout"). CONFIRMED_ERROR needs evidence of a second look or of a non-test use.

### MEDIUM

**M1. benchmark_fit PASS rests only on the declaration, although the data can contradict it (V11).** The check
computes the equal-weight universe itself and puts the benchmark-choice effect in its own evidence. It still returns
PASS when rules.yaml says `weighting: equal_weighted` and the series is cap-weighted. The PASS text says "Scope:
construction as declared". CONVENTIONS s.5 allows a declaration-only conclusion only when nothing can be contrasted,
and here something can. In this seed the choice effect was +1.04 pp/yr against a strategy gap of +0.40 pp, with TE
4.9%. In other words, the benchmark is not the equal-weight universe the owner says it is. Fix: when the
benchmark is declared to be built like the strategy and the equal-weight universe is computable, raise NEEDS_REVIEW
when the benchmark differs from that universe by more than a documented tolerance (tracking error between benchmark
and universe, or |choice effect|).

**M2. liquidity_participation judges each fill separately, so slicing defeats it (V16).** Five 8,000-share fills on
the same day make up 40% of ADV and the check still passes ("maximum participation 8.10%"). `day_qty` is already
aggregated per (ticker, day) for the over-day-volume rule but is not used for participation. Fix: compute
participation on the ticker-day total, as the impossibility rule does.

**M3. input_sufficiency counts arbitrarily stale fundamentals as present (V28).** The as-of lookup takes the latest
filing at or before the decision with no age limit. In the LockIn-like case, 18 of 100 members were scored through
2024 from filings of early 2022, and the check did not flag the test years. Fix: add
`conventions.max_input_age_days` (for example, 1.5 x the reporting frequency plus the filing lag). Older inputs
count as missing, and the default and its source should be documented.

**M4. liquidity_participation PASS covers only the trades it could measure (V17).** Eight of 16 trades (about 60% of
notional, 120,000 shares of a small cap) had no volume. They are counted as `trades_unmeasured`, which appears only
inside the metrics. The title still reads "Every trade below 10% of ADV". Fix: when any trade is unmeasured, say so
in the title ("8 of 16 trades measured"). Above a documented share of unmeasured notional, return NEEDS_REVIEW or
NOT_EXECUTABLE for the rest.

**M5. conditional_rule_activation silently drops a declared rule with no values on one side (V23).** `if not len(ai)
or not len(ao): continue` removes the rule from the evidence. The PASS then lists only the other rule. A declared
rule that was never computed in sample and is active in 81% of the test months is exactly the LockIn lesson. Fix:
report every declared rule. A rule with no in-sample values should be a NEEDS_REVIEW ("never exercised in sample"),
or at least a per-rule NOT_EXECUTABLE that blocks the global PASS.

**M6. stability_and_concentration PASS claims tests that did not run.** The title "No single subperiod, name or
handful of days carries the result" appears in these situations:
- under 3 calendar years the series is cut into halves, and the subperiod rule needs at least 3 subperiods, so it can
  never fire (V15 to V20, V27);
- under 250 periods the day test is skipped;
- with returns.csv there is no name test;
- with fewer than 3 names the name test is skipped. V27 passes while its own evidence says "Largest name contribution:
  EX2 108% of the P&L".

Fix: the title must name only the sub-tests that ran, and the skipped ones should be listed as not executable.

**M7. coverage_drift ignores `required_inputs`, which the docs list as one of its inputs (V04).** docs/INPUT_SPEC.md
and docs/CHECKS.md list `rules(required_inputs)` as an optional input of coverage_drift, but the code never reads it.
A discontinued field the model never used (esg_score 97% -> 0%) raises a high-priority NEEDS_REVIEW whose action is
"never spend a holdout on them". This one is disputable: the reviewer may want to know. But when required_inputs is
declared, undeclared fields should at most be INFO, under the package's own rule 3.

### LOW

**L1. Undocumented thresholds.** These constants change outcomes and are not in CHECKS.md or INPUT_SPEC.md (some
appear only in the procedure text of a finding):
- coverage_drift: MIN_PERIODS = 5 and MIN_HISTORY = 4. With 4 quarters or fewer, or in the first 4 periods, no drift
  can be flagged.
- liquidity_participation: at least 5 previous sessions with volume, or the trade is unmeasured; sigma from 60
  returns, at least 20.
- benchmark_fit: MIN_OBS = 20.
- dividend_corporate_actions: an event is "not discriminable" below 2 x adjustment_tolerance, which means dividend
  yields below about 0.2% go unchecked.
- stability_and_concentration: the INFO downgrade of the top-1%-days test depends on PSR vs psr_threshold.
- the 3-year cut-off between "calendar years" and "halves".

**L2. CONFIRMED_ERROR for orders above the day's volume assumes the volume is consolidated and in shares.** If
`volume` is primary-venue only, or is in currency (common in some BYMA exports), the error is not unambiguous.
INPUT_SPEC should state the unit and scope of `volume`.

**L3. coverage_drift without a universe uses "tickers present anywhere in the table".** A genuinely shrinking universe
without universe.csv then reads as drift. This is disclosed in the procedure. It is worth a sentence in CHECKS.md.

**L4. duplicates NEEDS_REVIEW on child fills with distinct trade_ids (V16).** The check's own text says that legitimate
partial fills have different ids. With distinct ids it should be INFO or PASS, not a review item.

**L5. V13 is caught as "ratio breaks without a declared event" rather than as a frozen price.** The frozen-price
search starts at the ex-date row itself, so a freeze that begins one session later is never reported as frozen, and
is not confirmed even though the as-traded series moves.

## 4. Audit of the alert-noise reduction (task 2)

Overall verdict: the INFO mechanism is principled. Its three rules are explicit, and INFO is never PASS. Most of the
39 reclassifications are defensible. Two things are not:

**D1 (dispute, methodological).** The 23 added expectations are counted as detections. The headline "63 / 63
expected detections met" (and "75 / 75") includes 23 expectations that were written **after** the tool produced
those findings. They are therefore not pre-registered and cannot fail by construction. The 0 "unexpected review" is
likewise reached by relabelling, not by the tool changing. Recommendation: report the 40 pre-registered detections
and the 23 post-hoc ones separately, and exclude the post-hoc ones from detection rates.

**D2 (dispute, inconsistent rule).** The P7 footprints of core/05 (`coverage`) and D03 (`coverage`, `price_jumps`)
were made expected detections. They are consequences of a problem that another check already judges:

```
cases/core/05_impossible_dates:  dates CONFIRMED_ERROR (future dates; not sessions) + coverage NEEDS_REVIEW
cases/data/D03_recycled_ticker:  ticker_identity CONFIRMED_ERROR + coverage NEEDS_REVIEW + price_jumps NEEDS_REVIEW
```

By the package's own INFO rule 1 ("the same evidence is already judged by another check"), the same rule used to
downgrade P3, these should be INFO notes pointing to `dates` and `ticker_identity`. Instead they became detections.
Rule 1 is applied when it removes alerts and not applied when it adds detections. R10 `price_jumps` is different: the
split jump *is* the planted problem. R11 `dates` is also different: the case description asked for it. Both are
legitimate.

**D3 (mild dispute).** The P1 threshold `significance_review_ratio = 2` was chosen with the battery in view. It falls
exactly in the empty band between the 14 cases at 1.1-1.7 x T (downgraded) and the 5 at 2.2-6.7 x T (kept). The
doc admits it is "a documented judgement". The INFO notes keep the PSR, so nothing is hidden. Still, a threshold
placed in the gap of the cases it is meant to separate needs an independent justification (for example, the size of
the PSR test under the null at that ratio) before the battery can be cited as supporting it.

**D4 (mild).** The P5 fix (1.96 -> 2.576) is statistically sound: an OR of two 5% tests has a size above 5%. But it
was triggered by one seed of an i.i.d. case crossing a 5% band, which is expected to happen 5% of the time. The
claimed combined size "close to 5%" is not measured anywhere in VALIDATION_EVIDENCE. A short Monte Carlo would
settle it.

Accepted as legitimate:
- P1 (b): 5 cases (MinTRL 2.2-6.7 x T).
- P1 (a): the R10 downgrade (Sharpe not positive).
- P2: R00 (CONVENTIONS s.5 requires it, the same as core 10).
- P3: N = 1 (exact duplication of the PSR).
- P4: S04, S05, S07 (direct consequences of the planted search).
- P6: 7 cases with zero cost and non-zero turnover (a real question for the owner, not noise).
- P7: R10 and R11.
- The 0.2.0 INFO uses in cost_sensitivity and protocol_integrity.

One reservation on stability_and_concentration's INFO rule. "The result disappears without its best 1% of days" is
evidence about concentration, not about significance. Folding it into sharpe_significance whenever the PSR is weak is
a stretch of rule 1, although no case exercised it.

## 5. Conclusion rule (task 3)

- PASS without verification: **6 confirmed instances**: H1 (V02), H2 (V14), M4 (V17), M5 (V23), M6 (V15 to V20,
  V27), and M1 (V11), which is a declaration-only PASS when contrast was possible. One cause repeats across them: the
  PASS branch is the `else` of "no problem found" and does not test whether the check examined anything. A generic
  guard would close the whole class: no PASS when the checked count is 0, or when a declared item was skipped.
- CONFIRMED_ERROR on ambiguous evidence: **2 confirmed** (H3 "inputs delivered in no table", H4 unknown purpose), plus
  the L2 caveat. The other CONFIRMED_ERRORs seen were unambiguous: V05, V08, V26 (c09 on the single-use window), and
  V27 (EX1 dividend inconsistent within its own series; order above day volume; declared minimum broken).
- Thresholds: the named conventions are documented (INPUT_SPEC "0.2.0 thresholds"). The hidden constants of L1 are
  not.

## 7. Prioritised fix list

1. **Generic PASS guard** (H1, H2, M4, M5, M6): no PASS when nothing was checked or a declared item was skipped. The
   title must state the sub-tests that ran.
2. **coverage_drift expected periods** (H1): use the membership, period, signal and trade spans, and count missing
   periods as 0%.
3. **input_sufficiency** (H3, M3): match names case-insensitively; NEEDS_REVIEW, not CONFIRMED_ERROR, when an input
   is in no table; add a staleness limit for as-of fundamentals.
4. **protocol_integrity** (H4): an unknown purpose is NEEDS_REVIEW; consider accepting `holdout` / `oos` as aliases of
   `test`, with a logged rename.
5. **dividend_corporate_actions** (H2, L5): NOT_EXECUTABLE without an as-traded series; ex-date drop test on the
   adjusted series; start the frozen search at the ex-date or the session after.
6. **liquidity_participation** (M2, M4): participation per ticker-day; disclose unmeasured trades and notional.
7. **benchmark_fit** (M1): contrast a declared "built like the strategy" with the computed equal-weight universe.
8. **conditional_rule_activation** (M5): never drop a declared rule silently.
9. **Battery reporting** (D1, D2): separate pre-registered from post-hoc expectations; apply INFO rule 1 to the P7
   footprints, or justify the exception.
10. **Docs** (L1, L2, L3, M7, D3, D4): document the hidden constants, the unit and scope of `volume`, and the
    required_inputs role of coverage_drift; justify the P1 ratio and measure the P5 combined size.
11. Add V02, V06, V10, V11, V14, V16, V17 and V23 (or equivalents) to the battery as pre-registered cases before
    fixing the code.
